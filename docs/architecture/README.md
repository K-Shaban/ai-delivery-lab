# System Architecture

## Overview

AI Delivery Lab is an end-to-end Data & AI delivery solution that transforms transaction data into customer inactivity-risk assessments and business-facing customer intelligence.

The architecture separates the solution into four main layers:

1. **Data** — transaction cleaning and customer-level feature engineering
2. **Machine Learning** — multiple models estimate inactivity risk and their probabilities are aggregated
3. **Application & AI** — FastAPI exposes predictions and Amazon Bedrock / Claude generates a business-facing explanation
4. **Deployment** — the prediction service is containerised and deployed using Amazon ECR and Amazon ECS / AWS Fargate

## End-to-End Flow

### 1. Transaction Data

The solution starts with the **Online Retail** transaction dataset.

The raw transaction data contains information such as:

- invoice numbers
- products
- quantities
- transaction dates
- unit prices
- customer identifiers
- customer countries

The raw dataset is cleaned before being used for modelling.

### 2. Data Preparation

The data preparation pipeline:

- removes exact duplicate transactions
- removes transactions without customer identifiers
- removes non-positive quantities
- removes negative unit prices
- standardises customer identifiers
- calculates transaction revenue

The resulting transaction data is used to construct the customer-level modelling dataset.

### 3. Customer Behaviour Features

Transactions are aggregated into customer-level behavioural features.

The current feature set includes:

- Recency
- Frequency
- Total Quantity
- Monetary Value
- Average Order Value
- Unique Products
- Country

These features provide the input to the inactivity-risk models.

### 4. Machine Learning

The solution currently evaluates three classification models:

- Logistic Regression
- Random Forest
- Gradient Boosting

Each model produces an estimated probability that a customer will become inactive.

The current implementation uses a **simple unweighted average** of the three model probabilities as the final risk probability.

This is an MVP ensemble rather than a calibrated or tuned ensemble model.

### 5. Business Risk Assessment

The aggregated probability is converted into a business-facing risk level:

| Risk Probability | Risk Level |
| ---: | --- |
| < 40% | Low |
| 40–69.9% | Medium |
| ≥ 70% | High |

The risk level is then mapped to a recommended business action.

For example, a high-risk customer is prioritised for retention outreach.

### 6. FastAPI Prediction Service

The model and customer-intelligence functionality are exposed through FastAPI.

The main endpoints are:

```text
GET  /health
POST /predict
POST /customer-intelligence
GET  /monitoring
```

`/predict` provides the structured risk assessment.

`/customer-intelligence` extends this flow by passing the model-derived customer assessment to Claude through Amazon Bedrock to generate a concise business explanation.

### 7. AI-Assisted Customer Intelligence

Claude does **not** determine the underlying risk probability.

The flow is:

```text
Customer Features
       ↓
ML Models
       ↓
Aggregated Risk Probability
       ↓
Business Risk Assessment
       ↓
Claude / Amazon Bedrock
       ↓
Business Explanation
```

This separation keeps the predictive component deterministic and traceable while using the language model for explanation and communication.

### 8. Containerisation and AWS Deployment

The FastAPI application is packaged as a Docker container.

The deployment flow is:

```text
Docker Image
     ↓
Amazon ECR
     ↓
ECS Task Definition
     ↓
ECS Service
     ↓
AWS Fargate
     ↓
FastAPI
```

The deployed service has been validated through its health and prediction endpoints.

The demo deployment can be scaled down when not in use to avoid unnecessary cloud costs.

## Architectural Principles

### Separation of responsibilities

Each component has a defined responsibility:

- **Data pipeline** — prepares reliable modelling data
- **Feature pipeline** — represents customer behaviour
- **ML models** — estimate inactivity probability
- **Risk aggregation** — combines model outputs
- **Business intelligence layer** — converts model output into operational guidance
- **FastAPI** — exposes the functionality as a service
- **Amazon Bedrock / Claude** — generates a business-facing explanation
- **AWS infrastructure** — runs the containerised service

### Traceability

The underlying risk assessment is generated by the machine-learning pipeline rather than by the language model.

This makes it possible to distinguish between:

```text
Prediction
    ↓
Model-derived probability

Explanation
    ↓
AI-generated business communication
```

### Incremental delivery

The architecture is intentionally modular so additional capabilities can be added without changing the core prediction workflow.

Potential future improvements include:

- model calibration
- more comprehensive monitoring
- improved risk thresholds
- additional customer behaviour features
- more advanced customer-intelligence workflows

These are intentionally outside the current MVP.
